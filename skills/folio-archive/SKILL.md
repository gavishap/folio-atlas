# Folio Archive — explicit invocation only

Read [the complete transfer and cleanup protocol](references/cloud-protocol.md) before any cloud operation or local cleanup. Use the shared `python scripts/folio.py backup` commands or this skill's `scripts/run.py backup` entry point. No Python upload connector or cloud credentials are bundled.

1. **Establish requested scope.** Sorting completion does not authorize this skill. A backup request authorizes packaging and the requested upload; it does not authorize any local deletion. Confirm the named target and an outside-target work directory. Explain that the personal backup contains the user's files and private project schema; it is not a public distribution package.
2. **Build.** Run `backup build --target TARGET --out WORK`. Record the archive, byte count, SHA256, build receipt, and local receipt key. Keep signed receipts/key outside all potential cleanup targets. The engine inventories files/directories, records links without traversing them, builds ZIP64, and rereads every archived file. Never run downloaded scripts.
3. **Transfer using actual capabilities.** Inspect available Drive tools. Use a connector/plugin only if it can upload/download the full binary archive at its size. Otherwise use approved browser controls or a manual transfer. Follow applicable computer-use instructions. Never bypass authentication/security blocks, silently install a transfer tool, store credentials, split/truncate the archive, or claim a successful upload from a filename alone. Record the observed cloud object URL/ID and inspect completion.
4. **Prove the cloud roundtrip.** Download that exact remote object to a distinct completed `.zip`; the original local ZIP, its copy, upload status, and matching length are not cloud evidence. Wait for completion without duplicating a running transfer. Run `verify-roundtrip` with the build receipt, actual downloaded archive, observed Drive URL, and a new restore directory outside the source. Require matching full ZIP SHA256/size, `complete=true`, every restored file hash, all files/directories present, and valid relative START HERE links/date/size records. No existing restore destination may be overwritten. Preserve failed restores and originals; report failures honestly.
5. **Stop unless cleanup was explicitly requested.** If requested, distinguish temporary backup copies from original source files. Inspect cloud object availability again. Generate `cleanup-preview` with the requested `copies`, `originals`, or `all` scope, plus every exact protected name. Review its preserved items and signed plan. Delete originals only if the user's request explicitly includes originals; never interpret “delete the backup” as “delete my files.” If scope is unclear, present the concrete preview and ask for that missing scope before deleting.
6. **Execute authorized cleanup.** Run the exact signed plan and confirmation ID only after cloud presence is confirmed, using `--cloud-available`. Add `--delete-originals` only for explicitly authorized original-file deletion. The proof expires after 24 hours. Current contents are SHA256-checked; changed/new/unbacked/protected/linked content stays. The engine unlinks individual verified regular files, removes empty verified directories, and retains the source root/private state/index. Never use wildcard/recursive deletion, change broad permissions, follow links, kill user apps, or delete anything from Drive.
7. **Report evidence.** Save and summarize the external final receipt, reclaimed bytes, protected hashes, preserved/failed items, and cloud link. A failed deletion is incomplete cleanup, even if verification passed. Stop any user-authorized monitoring when done; do not create a watcher or automation by default.

For a new computer, `backup restore --archive ZIP --destination NEW_FOLDER` verifies the manifest, preserves date information, validates links, and rebinds private metadata for future Refresh. Imported old undo history remains read-only. A standalone restore provides file-integrity evidence but never cloud-deletion authorization.
